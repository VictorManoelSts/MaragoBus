## Resumo

Implementada a sidebar desktop do Admin com os nove destinos solicitados, RouterLink,
ícones Lucide, rótulos textuais, indicação de página ativa e foco visível. A integração
reutiliza o slot desktop do AdminLayout. As novas páginas possuem somente título,
descrição e BaseCard de desenvolvimento futuro; a página inicial foi preservada.

A sidebar aparece a partir de lg (1024 px). Abaixo desse breakpoint ela fica oculta,
sem menu mobile, botão fictício ou espaço reservado. As páginas podem ser acessadas
diretamente por URL em telas pequenas.

Não foram implementados autenticação, permissões, estatísticas, CRUDs, formulários,
consultas, dados simulados ou API. Nenhum arquivo do Portal, componente compartilhado,
SVG ou dependência foi alterado. Não foram realizados commits ou pushes.

## Decisões técnicas

- **Configuração central:** sidebar e router consomem adminNavigationItems. As rotas,
  rótulos e ícones não são repetidos em uma segunda configuração. Essa lista poderá
  alimentar a navegação mobile posteriormente.
- **Organização:** lista plana na ordem solicitada: visão geral, pessoas, instituições e
  cursos, pontos de embarque, reservas e perfil. Não há submenus ou controles expansíveis.
- **Composição:** AdminShell é a rota pai e fornece AdminSidebar ao slot desktop de
  AdminLayout. As páginas filhas entram por RouterView. HomePage manteve seu título,
  descrição e card; apenas deixou de criar seu próprio wrapper para evitar layouts duplicados.
- **Largura:** sidebar de 256 px (`w-64`), links com altura mínima do token de controle
  de 48 px, ícones de 20 px e espaçamento consistente. Main mantém flex-1 e min-w-0,
  usando a largura restante sem max-width restritivo.
- **Rolagem desktop:** com slot desktop presente, o shell recebe lg:h-svh e
  lg:overflow-hidden; seu contêiner flex pode encolher com lg:min-h-0. O cabeçalho usa
  shrink-0. Sidebar tem h-full/overflow-y-auto, e main recebe lg:overflow-y-auto.
  Assim ambos rolam independentemente, sem calcular ou fixar a altura do cabeçalho.
- **Mobile:** as restrições de altura e overflow só se aplicam em lg. Abaixo disso,
  mantém-se o fluxo responsivo anterior, com a sidebar em display:none. Não há navegação mobile.
- **Acessibilidade:** nav com identificação “Navegação administrativa”, lista semântica,
  links nativos e ícones decorativos ocultos de leitores de tela. RouterLink fornece
  aria-current=page e a correspondência exata; Visão geral não permanece ativa nas demais rotas.
  O salto para o main e seu tabindex=-1 foram preservados.
- **Estilos:** fundo, texto, estado ativo, hover e outline usam apenas tokens existentes;
  peso tipográfico também diferencia a página ativa. A preferência por movimento reduzido
  desativa transições. Não foi criada uma paleta.

dos viewports, nove links, página ativa esperada, um único main e zero overflow horizontal.
Há uma navegação visível em cada desktop e nenhuma no mobile.

### Tela baixa e teclado

Em 1024 × 420 px, a sidebar dispõe de 328 px de altura e tem 496 px de conteúdo.
Foram enviados Tab pelo navegador: salto para o conteúdo, Visão geral, Alunos,
Motoristas, Faculdades, Cursos, Cursos ofertados, Pontos de embarque, Reservas e Perfil.
Ao chegar a Perfil, a sidebar rolou internamente 168 px, mantendo o link visível e o
cabeçalho na posição. O outline de foco estava visível. Enter foi enviado ao link Perfil.
Esse comportamento usa a interface atual; não foram inseridos dados simulados.

Os testes de navegador complementam as verificações estruturais de jsdom. Eles não
substituem validação em todos os navegadores, dispositivos ou tecnologias assistivas.

## Como visualizar

Na raiz frontend, execute:

```powershell
npm.cmd run dev:admin
```

Neste ambiente, caso o Node portátil não esteja no PATH da sessão:

```powershell
$env:PATH = "$env:LOCALAPPDATA\MaragoBus\tools\node-v24.22.3-win-x64;" + $env:PATH
npm.cmd run dev:admin
```

URLs principais:

- http://localhost:5174/
- http://localhost:5174/alunos
- http://localhost:5174/motoristas
- http://localhost:5174/cursos-ofertados
- http://localhost:5174/pontos-embarque

strictPort impede uma segunda instância na porta 5174.
