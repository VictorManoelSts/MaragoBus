## Resumo

Implementadas as três páginas provisórias do motorista, com sidebar desktop e barra inferior
mobile. Elas reutilizam PortalLayout, BrandLogo, BaseCard, ícones Lucide e os tokens neutros
existentes. Cada página tem somente título, descrição e card de implementação futura.

Não há dashboard, autenticação, permissões, dados simulados, consultas reais, integração REST
ou funcionalidades administrativas. As páginas são acessíveis diretamente pelas URLs.
Os cinco destinos e o conteúdo das páginas dos alunos foram preservados.

## Decisões técnicas

- Extração limitada da renderização de StudentNavigation para PortalNavigation: a lógica
  dos links, ícones e estados não foi duplicada. O wrapper anterior continua existindo.
- Cada perfil fornece seus próprios itens e identificação acessível: “Navegação do aluno”
  ou “Navegação do motorista”. Isso é composição de interface, não autorização de acesso.
- O grid mobile usa `repeat(items.length, minmax(0, 1fr))`: cinco colunas para o aluno e
  três para o motorista. Não são necessárias classes Tailwind construídas dinamicamente.
- RouterLink mantém os links nativos, a navegação por teclado e `aria-current="page"`.
  O estado ativo usa os mesmos tokens e estados de foco da etapa anterior.
- DriverLayout usa os slots já existentes de PortalLayout. As regras complementares
  `hidden lg:block` e `lg:hidden`, a região inferior sticky no fluxo e o padding de área
  segura permanecem iguais aos do aluno. Não foi alterado o PortalLayout.
- A página provisória foi apenas generalizada pelo nome para evitar três novos templates
  idênticos. Títulos e descrições vêm das rotas; nenhum dado de passageiros é exibido.
- A captura usa um Edge já instalado, com processo headless e perfil temporário separado
  do perfil pessoal. O protocolo de depuração é local e usa porta efêmera. O navegador
  de captura é encerrado ao terminar; o perfil descartável permanece no diretório TEMP.
- Referências para a captura: [Chromium headless](https://developer.chrome.com/docs/automation-and-testing/debug-headless),
  [Page.captureScreenshot](https://chromedevtools.github.io/devtools-protocol/tot/Page/)
  e [Emulation](https://chromedevtools.github.io/devtools-protocol/tot/Emulation/).

Os novos testes verificam acesso direto às três páginas, conteúdo estritamente provisório,

`minmax(0, 1fr)` para `minmax(0px, 1fr)` em jsdom. A asserção foi corrigida para aceitar
as duas formas equivalentes. A suíte final passou integralmente; não há falhas restantes.

- No mobile, barra entre y=771 e y=844; os cards terminam entre y=326,8 e y=390,8,
  permanecendo acima dela.

Essas evidências correspondem às páginas provisórias atuais em Chromium emulado.

larguras e condições possíveis.

## Como visualizar

Na raiz `frontend`, execute:

```powershell
npm.cmd run dev:portal
```

Neste ambiente Node/npm foram instalados de forma portátil na Etapa 01. Caso não estejam
no PATH da sua sessão, o comando completo é:

```powershell
$env:PATH = "$env:LOCALAPPDATA\MaragoBus\tools\node-v24.22.3-win-x64;" + $env:PATH
npm.cmd run dev:portal
```

Abra as três URLs da tabela de rotas acima. O servidor usa a porta 5173 com strictPort;
se ele já estiver rodando, basta abrir as URLs sem iniciar uma segunda instância.
